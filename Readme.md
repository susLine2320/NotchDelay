# 汎用ノッチ表示灯遅延プラグイン(NotchDelay.dll)
本プラグインは、BVE Trainsim において各種操作や表示（特にノッチ表示灯）に対して、**「応答遅延（Delay）」**、**「更新周期（Lag/カクつき）」**、および **「ゆらぎ（Jitter）」** を付加するための汎用ラグ・プロセッサです。

かつて公開されていた`Meter_digital.dll`（停P様）と同様の機能を備えています。
そのほか、`NotchNumber.dll`（あすく様）、TIMSプラグイン（Unicorn様・kikuike様・ろくらいん）、6・7号統合プラグイン（bve-i様）等を参考としています。

## 1. 基本仕様
- **標準ノッチ処理**: パワー、ブレーキ、レバーサーのハンドル入力に対し、共通の遅延設定を適用して指定パネルに出力します。
- **Customスロット (1〜6)**: 任意のパネル番号を指定し、そのパネルに書き込まれた値を読み取って個別のラグ設定を適用し、書き戻します。他プラグイン（TIMS等）が出力した表示値に対して、後付けでラグを付与することが可能です。
- **HbkBrakeオフセット**: 抑速ブレーキ等の段数表示において、内部的な段数に一定値を加算して出力できます。

### 設定ファイル
ファイル名は`NotchDelay.xml`とし、本体のファイル名に依存しません。設定値とデフォルト値は以下の通りです。

設定は `Core`（挙動・数値の設定）と `Panel`（出力先の割り当て）の2つのセクションで構成されます。

| Field | Brief | Value |
| :--- | :--- | ---: |
| **[Core]** | | |
| DefaultDelay | ノッチ出力を遅らせる時間[ms][1] | 500 |
| DefaultLag | ノッチ表示を更新する最小間隔[ms][2] | 100 |
| **DefaultJitter** | 更新タイミングに加算される最大ゆらぎ時間[ms][3] | 0 |
| HbkBrake | 抑速ブレーキノッチ数[4] | 0 |
| **Custom(1-6)** | 属性（`Delay`, `Lag`, `Jitter`）で個別挙動を指定。未指定時は `Default` 値を継承。 ||
| **[Panel]**[5] | | |
| Power | 力行ノッチ表示灯インデックス[6] | 216 |
| Brake | ブレーキノッチ表示灯インデックス[6] | 215 |
| Reverser | レバーサーインデックス[6][7] | -1 |
| Custom1〜6 | 任意項目フィルタ用インデックス[8] | -1 |

1. `Meter_digital.dll`と同様の機能。操作から表示開始までの時間を決定する。
2. `NotchNumber.dll`と同様の機能。表示が書き換わる最小の周期（カクつきのベース）。
3. **新機能。** （TIMSプラグインに`Jitter=250`相当で実装されていた）通信の不安定さや描画エンジンの特性による「更新タイミングのズレ」を再現する。実行時刻 $t$ に対し $(t \pmod{Jitter})$ の不定な待ち時間が`Lag`に加算される。
4. マスコンハンドルを逆回しするタイプのもの。表示値 $x$ は設定値 $a$ に対して $P(x+a)$,$H(-x+a)$,$N(a)$等として出力される。
5. 設定値を負とすると出力されない。
6. インデックスはATSパネル番号に対応。
7. 表示値は後退`0`、中立`1`、前進`2`。
8. 他のプラグインが出力したパネル値を読み取り、ラグを付加して再出力するフィルタ機能。`Core` セクションにて個別に `Delay`, `Lag`, `Jitter` の属性指定が可能。

#### XML設定例
`Core` で挙動を定義し、`Panel` で出力先を指定します。`Custom` 項目は属性を省略すると `Default` 値を継承します。

```xml
<?xml version="1.0" encoding="utf-8"?>
<NotchDelay>
  <Core>
    <DefaultDelay>500</DefaultDelay>
    <DefaultLag>100</DefaultLag>
    <DefaultJitter>50</DefaultJitter>
    <HbkBrake>0</HbkBrake>

    <Custom1 Delay="0" Lag="200" Jitter="250" />
    <Custom2 Delay="200" Lag="20" Jitter="0" />
  </Core>

  <Panel>
    <Power>216</Power>
    <Brake>215</Brake>
    <Reverser>-1</Reverser>
    
    <Custom1>10</Custom1>
    <Custom2>11</Custom2>
    <Custom3>-1</Custom3>
    <Custom4>-1</Custom4>
    <Custom5>-1</Custom5>
    <Custom6>-1</Custom6>
    </Panel>
</NotchDelay>
```

## 3. プラグイン解説
### Jitter（ゆらぎ）の詳説
新機能である **Jitter（ジッター）** は、デジタル通信特有の「不規則なゆらぎ」を再現するためのパラメータです。Jitterを重点的に、Delay・Lagと比較しながら詳しく解説します。

#### なぜJitterが必要か
現実の鉄道車両（特にTIMSやINTEROSなどの伝送系）では、データは一定周期で送られてきますが、モニターの描画エンジンや伝送路の混雑状況により、表示が更新される瞬間にコンマ数秒の「ズレ」が生じます。
Lag（固定周期）だけでは、メトロノームのように正確すぎる動きになり、デジタル機器特有の「時々一瞬止まったように見えて、直後にパッと動く」という挙動が再現できません。

#### Jitterの計算アルゴリズム
本プラグインでは、次回の更新時刻を以下の式で決定しています。

$$NextRefreshTime = CurrentTime + Lag + (CurrentTime \% Jitter)$$

* **Lagの部分**: 最低限待たなければならない「不感時間」です。
* **$(CurrentTime \% Jitter)$ の部分**: 実行時の時刻（ミリ秒）に応じて、0からJitter値までのランダムな待ち時間を加算します。

#### Jitterによる効果の差
* **Jitter = 0**: 
  規則正しいカクつき。FPS制限をかけたような、機械的でスムーズなコマ送りになります。
* **Jitter > 0**: 
  不規則なカクつき。例えば「200msで更新されるはずが、今回は250msかかり、次は210msで動く」といった変化が生まれます。これが視覚的に「通信の重さ」や「実車のモニタ感」として認識されます。

### Delay（応答遅延）の解説

Delayは、操作（入力）から表示が動き出すまでの **「タイムラグ」** を決定します。

* **役割**: 入力値を一定時間バッファ（貯蔵）し、指定時間が経過したものから順に取り出します。
* **視覚的効果**: ハンドルをガチャンと動かしても、画面上のノッチ表示がワンテンポ遅れてから動き出す状態を作ります。
* **Jitterとの違い**: Delayは「時間のズレ」を作るだけで、動きそのものの滑らかさには影響しません。

### Lag（更新周期）の解説

Lagは、表示が書き換わる **「最小ステップ」** を決定します。

* **役割**: 一度表示を更新したら、次に更新を許可するまで最低限待つ時間（ベース周期）です。
* **視覚的効果**: 値を大きくするほど、パラパラ漫画のように表示が飛び飛び（カクカク）になります。
* **Jitterとの関係**: 本プラグインにおいて、Lagは「最低周期」、Jitterは「そこに追加される不定な待ち時間」という親子関係にあります。

### 参考
- 当方公開のTIMSプラグインにおいては`Delay = 0, Lag = 200, Jitter = 250`相当となっています。
- 旧型のTISでは`Delay=750,Lag=500`程度のものもあるようです。

何度も調整することをお勧めします。

### Custom項目の「フィルタ処理」について

Customスロット（1〜6）は、以下のサイクルで動作します。

1.  **キャッチ**: 指定パネルの現在の値を読み取ります（他プラグインの出力後）。
2.  **フィルタ**: その値に対し、設定された `Delay`, `Lag`, `Jitter` で時間軸の加工を行います。
3.  **リリース**: 加工後の値を同じパネル番号へ上書き出力します。

これを利用することで、先行するプラグインが計算・出力している「速度」「電流」「圧力」などの表示に対して、本プラグイン側で「モニター風のカクつき」や「計器の応答遅れ」のみを抽出して付加することができます。
